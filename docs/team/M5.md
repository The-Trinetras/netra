# M5 — Windows client and accessibility

Read [ownership](ownership.md), [current scope](../architecture/current-scope.md),
[client rules](../../.claude/rules/client.md), [message flow](../architecture/message-flow.md)
and [runtime baseline](../architecture/runtime-baseline.md).

**Own:** C#/WPF desktop, accessible source selection, keyboard/NVDA, activation,
push-to-talk, press-to-interrupt, immediate STOP, speech/player controls and client
protocol. Session state is authoritative on the server; client caches are not commits.
Hands-free interruption, echo cancellation and braille are deferred. Browser extensions,
automatic screenshots, sonification and specialized code navigation are removed.

**Approved target:** complete PDF/lecture selection and study without a mouse or
sighted help. Keep focus/orientation stable and accessible text available when speech
fails. Activation does not open the microphone. Only final ASR submits a turn.
Pause video before a question; capture actual time and resume the same location.
Treat playback and analysis readiness separately. Never inspect unrelated browser tabs.

**Current source evidence:** [MainWindow](../../client/src/Netra.Desktop/Views/MainWindow.xaml)
defines a study transcript/control shell; it does not establish the full Library,
Study and player journey. [ConnectionManager](../../client/src/Netra.Desktop/Networking/ConnectionManager.cs),
[InterruptionController](../../client/src/Netra.Desktop/Audio/InterruptionController.cs)
and [binary frame processor](../../client/src/Netra.Desktop/Audio/BinaryAudioFrameProcessor.cs)
contain client mechanisms. The [project](../../client/src/Netra.Desktop/Netra.Desktop.csproj)
has no desktop web-view package declaration. NVDA and real-audio operation were not
verified by this migration.

**Shared boundaries:** [protocol v1](../../shared/contracts/protocol/v1/) with M1;
public question privacy/history with M4; visual/table structures and playback time
with M3. Preserve stable request IDs on retransmit and fresh frame identity; reject
late/cancelled/disconnected generations. Snapshot then the same persisted question
on reconnect; actual playback acknowledgement, not download completion, advances progress.

**Next integration work:** complete accessible selection/views/hotkeys/player,
server wiring and recovery. Review the proposed YouTube player/web-view dependency
and missing playback payloads with M1/M3. A total binary-frame size limit remains a
transport-hardening decision; the existing header framing stays unchanged.

**AX integration:** keep AX/Modal keys and SDKs out of WPF. Supply permitted local
measurements joined by existing request/generation identities, with any additional
transport reviewed by M1/M5. Measure actual STOP-to-silence on one client monotonic
clock, separate sent/played/acknowledged audio, and test response/STOP/recovery under
stalled tracing export. Provide actual Windows/NVDA/player results for M4's paired
reports; an LLM score cannot establish accessibility. Follow the
[AX plan](../architecture/arize-ax-integration.md) and [M5 prompt](prompts/M5.md).

**Acceptance target:** keyboard/NVDA source selection, focus, shortcut conflicts,
STOP latency, late audio, reconnect/retry, pending question and exact return. Record
real versus fixture audio and participant experience. Blindfolded teammates test
interaction only. No application checks were run here; see the
[report](../audits/documentation-migration-report.md).
