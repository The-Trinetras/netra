## What changed in this follow-up

**Slice A — Tutor / learning (`9eec4ea`)**
1. **INT-03, Tutor side.** `learning/tutor/evidence_versions.py` compares each
   handoff `EvidenceRef.source_version_id` (free string) with the resolved
   `Evidence.source_version_id` (UUID) as canonical UUIDs. Mismatch and
   *incomparable* (non-UUID, e.g. the contract example's `"src-ver-104"`) are
   refused, like an unresolved reference. `evidence_version` cannot be compared:
   `Evidence` has no version field.
2. **D2, first half — citation binding.** `QuestionDraft.evidence_ids` must bind to
   evidence the turn actually resolved (`quiz/validator.bind_draft_to_evidence`);
   binding runs **outside** the injectable grounding seam, so a test/composition
   seam cannot bypass it. `ApprovedQuestion.evidence_refs` stores the bound
   `{evidence_id, source_version_id, trust}`. The **support** half
   (`validate_draft_is_grounded`) still raises `NotImplementedError` — production
   remains fail-closed.
3. **Defect fixed:** a model-drafted question for a concept that was not requested
   was persisted under that concept. It is now refused.
4. **INT-09 — `TutorRunner`** (`learning/tutor/runner.py`) for M1 composition.
5. **INT-12, M4 part — trace facts** (`learning/tutor/trace_facts.py`): allowlisted,
   content-free attributes for M1's tracer. No telemetry library imported.
6. **D4 — factual projection.** Worker job projects one `ATTEMPTED` relationship per
   committed attempt from a self-contained outbox payload
   (`worker/.../learning_projection/neo4j.py`); API payload builder
   `learning/graph/factual.py`; cross-package contract test
   `tests/contract/test_learning_projection_payload.py`. Legacy `MasteryEdge`
   untouched.
7. **D3 — PROPOSED factual activity record** (`learning/history/`), not wired.

**Slice B — offline evaluation (`6926b83`)**: ordinal results, Prometheus templates +
strict parser, dataset snapshots/freeze gate, append-only artifacts with resume,

## Decisions previously recorded — revalidated

**D2 — optional-check grounding (M3 + M4, M2 for evidence storage).**
Reference binding is now implemented and enforced outside the seam; the **support**
definition is still unmade and production still fails closed. The injected
approving validator in tests remains a test seam, not grounding. Recommendation is
unchanged: bounded, non-agent entailment of each claim in prompt and answer key
against the bound evidence text, failures recorded not retried; alternatives are a
Tutor self-check (weak: checks itself) or a reviewed question bank (strong, but no
authoring pipeline). M3 input still needed: which multimedia-derived evidence is
eligible (M3 names `is_source_verified`, `citable_tables`, `supports_visual_claim` as
the gates; the resolver must only return evidence that passed them).

**D3 — factual history (M4 shape, M2 persistence, M1 wire, M5 presentation).**
Now a concrete PROPOSED module rather than a sketch. Changes from the earlier
proposal: `assistance_given` became `hint_generated` (generated ≠ delivered),
`student_reasoning_recorded` became `student_reasoning_stated` linked to an attempt,
`transcript_corrected` added with the original text kept, and delivery stages moved
into separate `DeliveryFact` records (sent/played/acknowledged) written only by the
path that observed them. The one optional handoff field
`utterance_provenance: {supersedes_prior_utterance: bool} | null` remains a proposal
for M1. No label field, no "untested" enum.

**D4 — attempt/outbox atomicity and projection (M2 + M4).** The projection shape
decision (factual `ATTEMPTED`, not `MasteryEdge`) is implemented on the M4 side. The
blocker is unchanged: M2 must provide an outbox-writing port callable from
`netra_api` inside the attempt transaction, and `propose_event` must then commit
attempt + `mark_answered` + outbox atomically (today they are separate calls on
in-memory Protocols). No worker `AuthContext` was invented.

**INT-03.** Tutor side done (canonical UUID compare, fail closed on incomparable).
Still needed from M1/M2: the canonical wire representation of `source_version_id`
(the committed example `"src-ver-104"` is not a UUID and is therefore refused), and
where `evidence_version` is represented so it can be compared at all.
