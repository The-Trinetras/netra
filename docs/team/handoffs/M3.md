## Changed signatures other owners should know about

- Worker multimedia payloads now share `ExtractObjectPayload`, whose
  index field is `object_index`. `ExtractFigurePayload.figure_index`,
  `ExtractEquationPayload.equation_index` and
  `ExtractTablePayload.table_index` remain as read-only properties, but
  the **constructor keyword changed** to `object_index`. Only M3 code and
  M3 tests construct these today.
- The multimedia job classes now take constructor dependencies
  (extraction/provider port, sink, stage recorder) instead of being
  no-argument stubs.
- `VideoEvidenceReference` now rejects `end_ms < start_ms` at
  construction rather than at first use, and carries an optional
  canonical `video_id`.

## What is implemented and checked

1. **Figure/chart exploration.** Axes, units, scales, series and plotted
   values are addressable with stable part IDs, each classified
   observed / generated / estimated / unreadable. `axes_established` is
   the single gate for "may Netra state what this graph shows".
2. **Table extraction semantics.** Headers, spans and cells with source
   mapping; `cell_at` resolves spans, `headers_for` keeps the header→cell
   relationship a prose summary destroys, `find_row_by_value` answers
   "where does the table show 2 A" deterministically.
3. **Basic-equation extraction.** `canonical_form` renders a fully
   parenthesized symbol string so signs, exponents, fractions and
   grouping are comparable; units are checked per operand;
   `extraction_source` only leaves GENERATED through a passing report.
4. **Validation against the original media.** A reviewer-authored
   `*SourceCheck` is the only thing that can verify extraction. No
   expectation means NOT_CHECKED, which never reads as a pass;
   unreadable-in-source produces a stated limitation rather than either
   a match or a mismatch.
5. **Layered navigation.** Pure, repeatable, no model call; IDs come from
   the stored structure, so nothing is re-labelled per request.
6. **Video identity and provenance.** Canonical `VideoAsset` kept apart
   from `ProviderAssetBinding`; every derived candidate carries provider,
   model name/version and producing stage.
7. **Playback vs analysis.** Two separate verdict types, each naming its
   reason, with no combined "ready" field anywhere. Transcript-only is a
   first-class outcome. YouTube playback defaults to
   `PLAYER_DEPENDENCY_PENDING`.
8. **Evidence at a captured player time.** `window_around` requires the
   time M5 captured; `resolve_moment_evidence` returns VISUAL /
   TRANSCRIPT_ONLY / NO_EVIDENCE_AT_TIME / NO_EVIDENCE so M1 can branch
   on an evidence gap rather than infer one.
9. **YouTube discovery and selection.** Contiguous 1..n numbering
   enforced by the model; selection by ordinal or pasted id resolves
   through the offered set and fails closed; ambiguous or unassessed
   relevance returns CLARIFY, never PROCEED.
10. **Adapter boundary.** Malformed Pegasus/Marengo responses (empty
    text, backwards range, range past media end, wrong embedding
    dimension, half a time range) are rejected before anything can cite
    them. Provider failures are Netra types with explicit retryability.
11. **Worker jobs.** Stage-recorded, replay-safe, cancellation- and
    deadline-aware; index reconciles against a recorded or existing
    provider asset id instead of re-indexing; extraction that failed or
    skipped its source check is stored but never marked citable.

## Pending decisions and boundaries, by owner

**M2 — persistence.** Three sinks are PROPOSED and unimplemented:
`TableCandidateSink.store_candidate`,
`ExtractionCandidateSink.store_candidate` and
`VideoEvidenceSink.store_candidates`, plus `ProviderBindingSink.bind`.
All are idempotent by `idempotency_key`; all must refuse to register
DERIVED evidence themselves. `StageRecorder` mirrors
`JobRepository.record_stage` for one claimed job and must reject a write
on a lost lease. M3 needs these implementations plus the migrations
behind them; M3 has not written any M2 file.

**M2/M1 — job payload schema.**
`netra_worker.jobs.multimedia.video.VideoEvidenceCandidateRecord`
duplicates `netra_api.multimedia.video.models.VideoEvidenceCandidate`
field for field, because the worker imports nothing from `netra_api` at
runtime. They are kept in step by hand. PROPOSED fix: a shared schema
under `shared/contracts/jobs/v1/`. That is a contract addition and needs
both owners' review; M3 did not add it.

**M1 — selection state and evidence gap.** `SelectedVideo` is the shape
M3 produces; the session service owns storing it and the last stable
result set. `MomentEvidence.sufficiency` is the value M1 should branch
on for the AgentSpec's step 3→4 strategy change. M3 has not added any
wire field for either.

**M1/M5 — playback boundary.** There is still no protocol message
carrying playback position, playback availability or analysis readiness
to the client; `shared/contracts/protocol/v1/` has none. M3 deliberately
invented none. PROPOSED shape, for M1/M5 to accept or reject:
a client→server field carrying `captured_player_time_ms` with the video
identity and the existing `expected_session_version`, and a
server→client payload carrying the two verdicts and their reasons
separately, never merged. Validation: time within known media duration;
replay by the existing request id; a stale position must be rejected
rather than answered.

**M5 — embedded player.** `PlaybackUnavailableReason.PLAYER_DEPENDENCY_PENDING`
is returned for every YouTube video until the web-view dependency is
approved and `embedded_player_available=True` is passed. That default is
intentional and should stay until the dependency decision lands.

**M4 — teaching.** `citable_tables`, `ValidationReport.is_source_verified`
and `MomentEvidence.supports_visual_claim` are the gates M4 should use
before treating multimedia content as fact. M3 asserts no teaching
policy.

**Unresolved inside M3.** `equations/mathml.py:render_mathml` remains
`NotImplementedError`. The required MathML fidelity is an unmade product
decision and the navigable `EquationNode` tree already serves
keyboard/NVDA exploration, so guessing a tag mapping would make it
policy by default. PROPOSED when it is decided: map
OPERATOR/OPERAND/FUNCTION/FRACTION/GROUP/SUPERSCRIPT/SUBSCRIPT to
`mo`/`mi`|`mn`/`mrow`/`mfrac`/`mrow`/`msup`/`msub`, driven by
`EquationNode.symbol` rather than `spoken_form`.

## Integration instructions

1. Implement the four sinks and `StageRecorder` against PostgreSQL (M2),
   then construct the jobs with them; nothing else about the handlers
   changes.
2. Build the extraction adapters that satisfy `ObjectExtractionPort` and
   `VideoDescriptionPort`. Each must run the matching
   `validate_*_against_source` and return the verdict with the
   structure — a port that returns a structure without a verdict makes
   everything downstream uncitable, by design.
3. Wire the Twelve Labs adapter behind `MarengoProvider` /
   `PegasusProvider`, converting every response through
   `twelve_labs_responses` and every failure through `providers.errors`.
   Keep `provider_index_id`, `model_name` and `model_version` as explicit
   configuration.
4. Wire the Tavily discovery adapter behind `VideoDiscoveryProvider`,
   passing its results through `number_results` before building a
   `DiscoveryResultSet`.
5. M1: call `evidence_at_player_time` with the position M5 captured, and
   treat `TRANSCRIPT_ONLY` as the recorded evidence gap that changes the
   next action.
6. Re-run the multimedia suites under real pytest once dependency setup
   is authorized, and record that run here replacing the substitute-runner
   results above.
